# SYSU Student Voice

举报/反映材料生成器是一个前端静态网站。当前 MVP 只聚焦“宿舍调整”事项，用于基于仓库中整理的事实、证据、诉求和反映对象生成正式材料草稿，并进行基础合规检查。

本项目定位为学生诉求材料生成与合规表达工具，不是自动发送工具，也不是攻击、煽动或批量骚扰平台。

## 项目目标

- 围绕宿舍调整、搬迁安排、过渡期、特殊困难处理机制等问题生成材料草稿。
- 基于结构化事实、证据、诉求和反映对象生成举报/情况反映、申诉材料或信息公开申请。
- 使用真实、克制、正式、程序性的表达。
- 在生成后提示高风险定性词、需要证据支撑的表达和疑似个人信息。
- 帮助用户在提交前核对事实、证据、措辞和个人信息。

## 项目不做什么

- 不自动发送邮件。
- 不做后台发信。
- 不做批量群发。
- 不保存用户填写内容。
- 不上传用户输入。
- 不支持造谣、侮辱、诽谤、人肉、公开隐私、冒名署名或批量骚扰。
- 不使用真实校徽、校名标识或官方视觉资产。

## 功能列表

- 固定宿舍调整场景，不再提供其他问题类型切换。
- 反映对象以展开列表展示，便于后续补充和核验具体渠道。
- 材料类型选择：举报/情况反映、申诉材料、信息公开申请。
- 从 JSON 数据加载事实、证据、诉求和反映对象。
- 生成正式 Markdown 文本。
- 合规检查：高风险词、需证据表达、疑似手机号、身份证号、邮箱、宿舍号等。
- 复制正文。
- 下载 Markdown。
- 打开邮件草稿，用户必须自行审阅后发送。

## 如何添加事实材料

编辑 `data/facts.json`。当前具体事实材料只是示例占位，后续可以继续补充。新增条目时建议包含：

- `id`：事实编号，如 `F004`。
- `caseId`：固定使用 `dorm-relocation`。
- `title`：事实标题。
- `date`：发生或通知日期，不确定时使用谨慎格式。
- `content`：原始描述。
- `safeWording`：生成材料时采用的中性表述。
- `status`：核实状态，如 `collecting` 或 `pending-verification`。
- `evidenceIds`：关联证据编号。
- `riskLevel`：风险等级。

事实描述应当可核查、可说明来源，不应加入未经证实的动机推断或攻击性评价。

## 如何添加证据材料

编辑 `data/evidence.json`。当前材料结构先保持不变，新增证据前必须完成脱敏。建议填写：

- `id`：证据编号。
- `title`：材料标题。
- `type`：材料类型，如 `notice`、`photo`、`document`。
- `path`：材料路径或公开链接。
- `date`：材料日期。
- `source`：来源说明。
- `redacted`：是否已脱敏。
- `description`：材料说明。

未脱敏材料不应提交到仓库。截图、照片、聊天记录和文档应遮盖姓名、学号、手机号、身份证号、宿舍号、门牌号、人脸、车牌、头像、昵称和私人联系方式。

## 如何添加反映对象

编辑 `data/targets.json`。当前反映对象先以较完整的类型清单展示，具体公开渠道、邮箱或网页后续再补充和核验。新增对象时建议包含：

- `id`：对象编号。
- `name`：对象名称。
- `type`：校内反映、信息公开、校内监督、外部反映等。
- `recipientLabel`：生成材料中的称谓。
- `email`：公开邮箱，可留空。
- `website`：公开网页，可留空。
- `recommendedTemplate`：推荐模板。
- `description`：适用场景。

只应添加公开、正式、可核验的渠道信息，不应加入私人手机号、私人邮箱或个人社交账号。

## 合规与隐私原则

- 使用中性、事实性、程序性表达。
- 严重指控必须有充分证据支撑。
- 不公开他人隐私或可识别个人信息。
- 不冒用他人身份。
- 不代表未经授权的其他同学。
- 不鼓励刷屏、骚扰或批量提交。
- 用户应在提交前自行核对事实、证据、措辞和个人信息，并对自己提交的内容负责。

## 贡献指南

欢迎提交：

- 官方通知截图或公开网页链接。
- 已脱敏聊天记录。
- 公共区域照片。
- 个人经历描述。
- 渠道补充。
- 模板建议。
- 事实纠错。
- 合规风险提醒。

不接受：

- 未脱敏材料。
- 侮辱性内容。
- 无证据严重指控。
- 私人联系方式。
- 人肉信息。
- 鼓励骚扰或刷屏的内容。
